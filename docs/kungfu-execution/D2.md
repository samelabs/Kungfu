## Required（每条 ↔ 协议条款）

1. `threads(code, subject, status∈{open,closed}, key_hash, key_role, next_seq)`；单在用钥匙三字段同组（§6.1）。
2. `thread_members(thread_id, account_id, role∈{governor,speaker,observer}, joined_via_key_hash, joined_at)`；UNIQUE(thread_id, account_id)；两事实持久（§6.2）。
3. `thread_idempotency(account_id, tool, key, request_hash, result_snapshot)`；D2 全部写工具接入：同 key 同请求返回 `result_snapshot` 原样（首次成功结果的协议事实字段，不重投影当前对象）；同 key 异请求 `IDEMPOTENCY_CONFLICT` 且无副作用（L3）。
4. `thread_start(subject?, key?)`：创建即 open，创建者 governor；`key=true` 同事务签发首钥（L2 组合）。
5. 钥匙：`kf_`+32hex 服务端只存 sha256；签发新钥同事务作废旧钥；`thread_key_revoke` 单独作废；原文仅签发首次成功响应出现，幂等重放返回原结果的非秘密字段（fingerprint）不重披露原文（§6.1、L3）。
6. `thread_join(key)`：加入是动作，仅活跃账户（§6.1）；重复持有效钥 join 返回既有成员资格，无新效果（L2）；失败限流 20 次/15 min 统一 `KEY_INVALID`（§2 数值）。
7. 成员与治理：`thread_leave`（开放与已关闭均可）；`thread_remove`/`thread_set_role`（治理专属）；开放房必须 ≥1 governor——leave/remove/降级三路径在会破坏该条件时 `LAST_MANAGER`（§6.2）。
8. `thread_close`：终态；钥匙作废（清 key 三字段）；成员资格保留转只读；成员仍可 leave（§6.5）。房间面无条目，收束义务/作废分派为空操作占位（D3/D4 落地时替换）。
9. 停用级联（§4）：账户停用挂点处——其全部成员资格终止；若致开放房 0 governor，该房同一事务中关闭（效果同 thread_close）。
10. 上限：单房成员 ≤50、每账户开放房 ≤100（L4 数值）；`thread_get` 返回房间结构+本人角色+成员表（时间线/义务字段为空占位）；`thread_list(status?, cursor?)` ≤50/页。
11. 全部写工具接入 `idempotency_key`（信封含 `next_action`/`next[]`/`retry_after`，沿用已部署信封构造）。

## 负测（必须）

- 旧钥 join：`KEY_INVALID`；作废后同理（A5）
- 重复 join：返回既有成员资格且 role 不变、无新增成员行（A7）
- LAST_MANAGER 三路径：leave/remove/set_role 全拒（A8）
- 非治理者调 key/remove/set_role/close：`NOT_GOVERNOR`（A16 房间部分）
- 已停用账户 join：拒（A15 部分）
- 非成员 thread_get：`NOT_MEMBER`；旁观成员只读（A16 部分）
- 上限：第 51 名成员、第 101 个开放房：拒（A24 部分）
- 幂等：同 key 异请求 `IDEMPOTENCY_CONFLICT` 零副作用；start 后改 subject 重放 start 返回首次快照；key 签发重放不重披露原文（A5/A6 部分——快照断言本阶段限 start/key/join/close 四工具）
- 并发：双方同时 join 恰好一个成员行；并发 close/join 先后串行化（L5）
